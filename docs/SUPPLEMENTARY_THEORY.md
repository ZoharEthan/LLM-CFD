## 1. 双向验证机制（正文§3.4引用）

LLM-CFD的双向验证机制允许LLM在正向（数据→规则）和反向（规则→数据）两个方向上进行验证。

**正向验证**（数据→规则）：LLM从数据样本中推断候选CFD规则，统计验证门控筛选通过验证的规则。这是主流程的核心路径。

**反向验证**（规则→数据）：给定已验证的CFD规则集合，LLM检查数据中是否存在"满足所有规则但仍有语义异常"的记录。这一方向利用LLM的语义理解能力发现规则未覆盖的异常，对应§3.6多层级风险检验中的L2/L3层。

反向验证的定量评估（基于500条候选记录的初步实验）显示L1+L3融合可提升AUPRC 1.8%，但L2/L3层的边际贡献有限，主实验采用L1-only配置。完整分析见本文档§3。

## 2. CFD规则冲突消解近似分析（正文引用）

### 2.1 问题定义

给定经验证通过的CFD规则集合Σ（含fd/enum/range/logic/consistency五种类型），两条规则φ_i和φ_j冲突当且仅当存在元组t使得t同时违反两者但修复其一将违反另一（即规则间存在修复依赖）。目标是找到基数最大的无冲突子集Σ_max ⊆ Σ。

### 2.2 四步流程

1. **LLM语义预检**：对|Σ|×(|Σ|-1)/2个候选规则对，LLM基于自然语言描述标记可能冲突的对（标记为conflict/maybe/safe三级），保留conflict和maybe对进入精确验证。
2. **精确验证**：对预检保留的候选对，构建反例测试元组集，验证是否真正存在修复依赖。
3. **LLM引导消解**：对确认冲突的规则对，LLM建议保留语义优先级更高的规则（如consistency > logic > range > enum > fd）。
4. **贪心近似**：基于消解建议构建冲突图G=(Σ, E)，其中E为确认冲突边，在G上运行贪心独立集算法。

### 2.3 命题2的近似保证证明概要

设LLM预检的召回率为r（即r比例的真实冲突对被保留进入精确验证），精确验证的精确率为1（验证不引入假阳性）。

- 当r=1时，贪心算法在完整冲突图上运行，由NP-hard性知精确求解不可行，但标准贪心独立集保证|Σ_m| ≥ (1-1/e)|Σ_max|。
- 当r<1时，贪心算法在不完整冲突图G'上运行，G'的边集E'⊆E，因此Σ_max也是G'的独立集，故|Σ_m| ≥ (1-1/e)|Σ_max|仍成立。

近似比随r→1趋近1-1/e，实际中LLM预检的高召回率（实验中r≈0.9）使近似质量接近理论最优。

### 2.4 复杂度分析

LLM预检为O(|Σ|²)次API调用（可批量化），精确验证为O(|E'|)次反例测试（本地计算），贪心独立集为O(|Σ|+|E'|)。在本文实验中|Σ|=23，候选对253个，LLM预检保留约30个（12%），验证后确认冲突约8对，贪心在毫秒级完成。当|Σ|增至数千条（如CFDMiner的7755条），LLM预检的开销可能变得不可忽略，此时可采用采样预检或基于规则类型的快速过滤策略。

### 2.5 实证评估计划

在扩展实验中，将使用CFDMiner发现的7755条常量CFD作为大规模规则集，比较LLM预检+贪心与纯贪心的近似质量和运行时间，验证LLM预检在大规模场景下的实际加速效果。

## 3. 多层级数据质量风险检验（正文§3.6引用）

### 3.1 三级体系

- **L1模式级**（CFD梯度违规评分）：即§3.3核心方法，通过矩阵运算高效检测CFD规则违规。
- **L2语义级**（LLM识别CFD未覆盖的语义异常）：LLM判断记录是否存在逻辑矛盾、不可能的值组合。
- **L3业务级**（LLM检测违反行业常识的取值组合）：LLM判断记录是否存在违反电信行业常识的取值（如负消费、不合理套餐组合）。

风险评分：Risk(t,Σ) = α·V_CFD(t) + β·V_LLM_sem(t) + γ·V_LLM_biz(t)

### 3.2 实验设计

从L1评分（V_CFD）排名前500的候选记录中，以每批10条记录的方式调用DeepSeek-V4-Flash（temp=0.0），分别进行L2语义级判断和L3业务级判断。共计100次API调用（50批×2层）。

### 3.3 详细结果

| 配置 | AUPRC |
|------|-------|
| L1 单独 | 0.495 |
| L2 单独 | 0.250 |
| L3 单独 | 0.398 |
| L1+L2 (α=0.8, β=0.2) | 0.487 |
| L1+L3 (α=0.7, γ=0.3) | 0.504 (最优，+1.8%) |
| L1+L2+L3 (α=0.6, β=0.2, γ=0.2) | 0.501 |
| L2+L3 (β=0.5, γ=0.5) | 0.312 |

### 3.4 深入分析

1. L2层单独性能低于L1（0.250 vs 0.495），原因在于LLM对单条记录的语义一致性判断受到上下文窗口限制——LLM需要同时记忆23条CFD规则并判断记录是否违反，而L1层的梯度违规评分通过矩阵运算高效且精确地完成此任务。
2. L3层性能介于L1和L2之间（0.398），表明业务常识知识对异常检测有补充价值，但受限于LLM的业务知识覆盖面。
3. 最优融合L1+L3仅提升1.8%，说明L1层已捕获了大部分可通过规则检测的异常，L2/L3层的边际贡献有限。这一结论支持主实验采用L1-only配置的决策。
4. L2+L3融合（0.312）远低于L1单独（0.495），表明LLM的语义和业务判断不能替代形式化规则检测，只能作为补充。

### 3.5 局限性

本验证基于500条候选记录（全数据集7%），统计结论的稳健性有待更大规模实验验证。L2/L3层的提示词设计可能影响性能，更精细的提示工程（如few-shot业务规则示例）可能提升L3层的贡献。

## 4. 形式化框架完整定义（正文§3.7引用）

### 定义3（CFD规则空间与形式化语义）

给定关系模式R(A₁, ..., A_d)，CFD规则空间Φ(R)定义为所有可能的条件函数依赖φ的集合，其中每条φ具有形式(X → A, T_p)，X为条件属性集合，A为依赖属性，T_p为模式表。规则类型集合Type = {fd, range, enum, logic, consistency}，每条φ关联一个类型标签τ(φ) ∈ Type。

模式表T_p的值域为Dom ∪ {'_'} ∪ I(R) ∪ P(X) ∪ F(X)，其中Dom为属性值域，'_'为通配符（任意值），I(R)为数值闭区间集合[a,b]，P(X)为谓词函数集合，F(X)为跨属性计算函数集合。

元组t对条件模式的匹配定义为：t ≼_X T_p当且仅当∀B ∈ X，t[B]与T_p[B]兼容（常数要求相等，'_'匹配任意值，谓词要求P(t[X])为真）。

满足性语义：t ⊨ φ当且仅当t ≼_X T_p蕴含t[A]满足T_p[A]指定的依赖约束。

五种CFD类型的形式化对应：
1. **fd类型**（标准变量CFD[3]）：T_p[B]='_'，T_p[A]='_'，语义为X的取值确定A的取值。
2. **enum类型**（标准常量CFD[3]）：T_p[B]为常数，T_p[A]为常数或有限值域集合，语义为t ≼_X T_p → t[A] ∈ T_p[A]。
3. **range类型**（边界CFD）：T_p[A]=[min, max]∈I(R)，语义为t ≼_X T_p → T_p[A].min ≤ t[A] ≤ T_p[A].max。
4. **logic类型**（扩展CFD，eCFD）：T_p包含谓词P(X)，语义为P(t[X]) → t[A]满足T_p[A]指定的逻辑关系。
5. **consistency类型**（计算依赖CFD）：T_p包含跨属性计算函数f(X₁,...,X_k)，语义为|t[A] - f(t[X₁],...,t[X_k])| ≤ ε。

### 定义3a（条件支持度与置信度）

- 条件支持度：cond_support(φ) = |{t ∈ D : t ⊨ condition(φ)}| / |D|
- 置信度：confidence(φ) = |{t ∈ D : t ⊨ condition(φ) ∧ t ⊨ dependency(φ)}| / |{t ∈ D : t ⊨ condition(φ)}|

统计验证门控保留cond_support ≥ θ_s且confidence ≥ θ_c的规则。

### 命题1（CFD验证的不变性）

LLM的引入不改变CFD验证的严格性。若元组t违反某CFD规则φ，则V_CFD(t) > 0（LLM不干扰形式化检测）；LLM仅提供额外的语义风险信号V_LLM(t)，不降低V_CFD的检测灵敏度。

### 命题2（冲突消解近似保证）

设LLM预检的召回率为r，精确验证的精确率为1。则贪心独立集算法保证|Σ_m| ≥ (1-1/e)|Σ_max|，与r无关。

## 8. 真实世界数据质量验证（原正文§4.5.5）

### 8.1 实验设计

为弥补注入式异常评估的生态效度局限，利用Telco数据集自身的真实数据质量问题进行非注入式验证。该数据集包含两类自然错误：

1. **TotalCharges字段以空字符串编码缺失值**（11条记录，0.16%），属于编码规范违规。
2. **TotalCharges与tenure×MonthlyCharges的一致性偏差超过10%的记录**（381条，5.41%），可能源于按比例计费、促销折扣等业务复杂性。

合计392条自然错误（错误率5.57%），远低于注入实验的18%。

### 8.2 实验结果

| 方法 | AUPRC | 相对于随机基线 |
|------|-------|---------------|
| 随机基线 | ≈0.056 | 1.00× |
| COPOD | 0.040 | 0.71× |
| EIF | 0.048 | 0.86× |
| LLM-CFD | 0.066 | 1.18× |

LLM-CFD在自然错误上的AUPRC=0.066，高于EIF（0.048，1.37倍）和COPOD（0.040，1.65倍），但绝对性能较低（随机基线≈0.056）。

### 8.3 分析

1. **LLM-CFD仍保持相对优势**：证实其核心价值不依赖于注入方案与规则的结构性对应。
2. **绝对性能下降符合预期**：自然错误中381条为一致性偏差，其中部分可能源于合法的业务复杂性而非真正的数据质量问题，且LLM-CFD的consistency规则容差阈值（ε）与10%偏差判定标准不完全对齐。
3. **Type 1错误检测率低**：在空字符串编码错误上，LLM-CFD检测率18.2%，低于EIF的45.5%，因为空字符串经预处理后变为0，与tenure=0的新客户期望值重合，LLM-CFD的consistency规则未能将其标记为违规。

### 8.4 核心贡献

以真实数据证实LLM-CFD的优势并非完全来自注入偏差，同时诚实地展示了方法在非语义违规场景下的性能下降，与Adult数据集结果（AUPRC=0.218<EIF=0.227）共同界定了方法的适用边界。
